## 已确认的任务范围

Codex、ZCode 和 Gemini 各自成组。Gemini 网页与 Antigravity 的聊天共用 Gemini 组，详情逐条显示 Web 或 Antigravity。同一段 Antigravity 聊天切换模型仍占一个任务位。网页未连接时显示来源提示，Antigravity 已读到的任务保留。所有来源都就绪且没有任务时，收起整条任务栏。[来源详情示例](origin-detail.png)

| 方案 | 参考和用途 | 取舍 |
| --- | --- | --- |
| A 三组并排 | 沿用现有来源胶囊与状态圈，三组使用已批准玻璃图集中的空仓材质。[来源胶囊](../../verification/task-source-capsules/native-capsules.png) · [材质](../../../src/gemini-glass.webp) | 三个来源可以同时扫视。每组显示至多三项，任务更多时保留前两项并显示余数。 |
| B 来源切换 | 采用项目分段选择器的选中反馈，第二行留给任务名称。[分段控件](../../../src/PlanSegmented.tsx) | 所选来源的前两项直接显示名称，其他来源保留计数与提醒灯。 |
| C 待处理优先 | 沿用现有任务详情的状态、任务名层级与玻璃底板，将重要任务提到主栏。[任务详情设计](../task-status/DESIGN.md) | 直接显示第一项报错或等待，查看其余来源需要展开「全部」。 |

## 验收边界

在 Windows Edge 通过本地文件打开了交互稿，并检查了三个方案在 300 px、260 px 下的常态、拥挤、网页未连接、Gemini 离线和全部空闲。检查项目包括任务按钮边界、切换来源、展开列表和 Esc 返回。

选定方向后，桌面程序需要单独验证两入口的任务发现、模型切换去重、真实状态和打开原聊天。正式交付时对照相同宽度下的原生截图。现有 Gemini 额度探针提供的百分比和刷新时间只用于额度仓。
